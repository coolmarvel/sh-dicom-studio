# 프로젝트 브리프: sh-dicom-studio

## 한 줄 정의

병원 검사실·전산실을 위해, 검사장비가 출력하는 JPG/PDF 등 일반 이미지를 환자·검사정보와
묶어 의료영상표준 **DICOM 파일로 변환·저장·조회**하는 크로스플랫폼 데스크톱 앱
(상용 프로그램 VPWinGate / DICOM Studio 의 재구현).

## 문제와 사용자

- **문제**: 병원의 검사장비들은 결과를 JPG·PDF 같은 일반 파일로 내놓는다. 이걸 PACS 에
  넣으려면 환자정보와 연결해 DICOM 으로 변환하는 게이트웨이 프로그램이 필요한데,
  현재 쓰는 상용 제품(VPWinGate 등)은 윈도우 전용·유료·소스 비공개라 내부 동작을
  이해할 수도, 직접 고칠 수도 없다. 직접 만들어 구조를 이해하고 유지보수 가능한
  대체품을 확보한다.
- **사용자 유형**:

| 유형 | 이 앱에서 하는 일 |
|---|---|
| 검사실 사용자 | 이미지를 열고 → 환자·검사정보 입력 → DICOM 변환·저장 → 필요시 다시 검색·조회 |
| 전산 관리자(제작자 본인) | 저장 경로·기본 Modality·레이아웃 등 옵션 설정, 배포(인스톨러) 관리 |

## 핵심 시나리오 (v1.0 에 반드시 되어야 하는 것)

1. 사용자가 JPG/PNG/BMP/TIFF 이미지를 열어서 뷰어에서 본다.
2. 사용자가 환자·검사 정보(Patient ID, 이름, 성별, 생년월일, Modality, StudyDate,
   StudyDesc, AccessionNo 등)를 입력하고 열린 이미지들을 **DICOM 파일로 변환·저장**한다.
3. 사용자가 저장된 검사를 로컬 데이터베이스에서 환자ID·이름·날짜로 **검색해 다시 열어 본다**
   (SaveDB / FindDB).
4. 사용자가 변환 전에 이미지를 회전·반전·색반전·확대(Zoom/Pan/Fit/RealSize)·순서변경·삭제로
   정리한다. 뷰어는 그리드 레이아웃(1×1~4×4)과 페이지 넘김을 지원한다.
5. 사용자가 기존 DICOM(.dcm) 파일을 열어서 본다.
6. 사용자가 윈도우·맥·리눅스 어디서든 **인스톨러로 설치**해서 쓴다.

## 제약

- **플랫폼/형태**: 데스크톱 앱 (윈도우·맥·리눅스 3-OS), 인스톨러 배포. 1차는 서버 없이
  **오프라인 완결** — 네트워크·도커 불필요.
- **기간/리듬**: 기한 없음, 퇴근 후·주말 사이드 프로젝트.
- **비용**: 0원 — 오픈소스 라이브러리만 사용.
- **기타**: 혼자 개발·병원 내 소규모 사용. 실환자 정보는 개발 중 사용하지 않는다(테스트
  더미 데이터만). 참고 명세는 `docs/reference/` 의 VPWinGate 매뉴얼 요약.

## 성공 기준

- 사용자 본인의 말: **"DICOM Studio 처럼 이미지 불러오고, DICOM 파일로 변환하고,
  뷰어로 볼 수 있는 정도"** — 이 세 가지가 되면 v1.0.

## 범위 밖 (이번에 안 하는 것)

- **로그인(ID/PW)** — 2차. 서버 인증으로 처음부터 구현하기로 결정.
- **서버·Oracle·도커** — 2차. ASP.NET Core Web API + Oracle 을 도커로 띄워 계정·검사
  메타데이터를 서버화.
- **DICOM Send / Multisend (PACS 전송)** — 3차. 도커에 Orthanc 를 띄워 테스트 예정.
- **DICOM Modality Worklist** — 4차.
- **장비 연동** (VP I/F 폴더 감시 서비스, 스캐너/TWAIN, 풋스위치, F2 캡처) — 하드웨어가
  필요해 보류.
- **전자동의서 서명(JAIT.sign 류)** — 별도 프로젝트로 분리. 이 앱의 이미지→DICOM 코드를
  재활용할 수 있을 때 시작.
